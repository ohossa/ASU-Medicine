# AI Tutoring Hints — Setup Guide

This document explains how the AI-powered tutoring hints system works and how to configure it to use a real AI provider.

## How it works

When a student answers a question incorrectly **twice in a single session**, a contextual hint appears below the question. The hint is generated by an AI provider adapter and is designed to be Socratic — guiding the student toward the correct answer without giving it away.

### Frontend flow
1. `useHintSystem` hook (in `src/app/hooks/useHintSystem.ts`) tracks wrong-answer counts per question index.
2. After the second wrong attempt, the hook sends a POST request to `/api/hint` with the question text, options, explanation, subject, and prior attempts.
3. The `HintPanel` component (`src/app/components/HintPanel.tsx`) slides in with an amber-themed card showing the hint.
4. The student can dismiss the hint or proceed to answer again.

### Backend flow
1. `api/hint.ts` receives the request after Clerk JWT verification.
2. Rate limiting (10 hints/minute per user) is enforced via Redis/Upstash.
3. The configured `AIAdapter` generates the hint text.
4. The response is returned as JSON: `{ hint: string, source: string }`.

## Providers

The backend uses a pluggable adapter pattern. Set `HINT_AI_PROVIDER` to choose:

| Provider | Env vars required | Description |
|----------|-------------------|-------------|
| `static` (default) | None | Returns subject-tailored generic hints. Zero cost, works offline. |
| `openai` | `OPENAI_API_KEY` | Calls OpenAI Chat Completions (`gpt-4o-mini` by default). |
| `google` | `GOOGLE_GENAI_API_KEY` | Calls Google Gemini API (`gemini-1.5-flash` by default). |

## Configuration

### For Vercel / production

Add these environment variables in your Vercel dashboard:

```
HINT_AI_PROVIDER=openai
OPENAI_API_KEY=sk-...
OPENAI_HINT_MODEL=gpt-4o-mini
```

Or for Google:

```
HINT_AI_PROVIDER=google
GOOGLE_GENAI_API_KEY=...
GOOGLE_HINT_MODEL=gemini-1.5-flash
```

Or for NVIDIA NIM:

```
HINT_AI_PROVIDER=nvidia
NVIDIA_API_KEY=nvapi-your-key-here
NVIDIA_HINT_MODEL=meta/llama-3.1-70b-instruct
```

### For local development

Create or edit `.env.local`:

```bash
HINT_AI_PROVIDER=openai
OPENAI_API_KEY=sk-your-key-here
```

### To stay on static fallback

```bash
HINT_AI_PROVIDER=static
```

This requires no API key and still gives students helpful, subject-specific hints.

## Adding a custom provider

1. Create a new class implementing the `AIAdapter` interface in `api/hint.ts`:

```ts
class MyProviderAdapter implements AIAdapter {
  async generateHint(req: HintRequest): Promise<HintResponse> {
    // Your API call here
    return { hint: '...', source: 'custom' };
  }
}
```

2. Wire it in `getAdapter()`:

```ts
function getAdapter(): AIAdapter {
  const provider = (process.env.HINT_AI_PROVIDER ?? 'static').toLowerCase();
  switch (provider) {
    case 'openai': return new OpenAIAdapter();
    case 'google': return new GoogleGenAIAdapter();
    case 'myprovider': return new MyProviderAdapter();
    default: return new StaticFallbackAdapter();
  }
}
```

3. Add any required env vars to your deployment config.

## Rate limits

- **Frontend**: Requests are debounced by 400ms and cached for 5 minutes.
- **Backend**: 10 hints per minute per user (tracked via Redis/Upstash).
- If rate-limited, a friendly static message is shown instead.

## Testing hints locally

1. Start the dev server: `npm run dev`
2. Sign in via Clerk.
3. Start a quiz and intentionally answer a question incorrectly twice.
4. The amber hint panel should slide in.
5. If `HINT_AI_PROVIDER=static`, you'll see a generic subject hint.
6. If `HINT_AI_PROVIDER=openai` and you have a key set, you'll see an AI-generated Socratic hint.

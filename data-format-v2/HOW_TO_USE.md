# How to Use ASU Portal Data Format v2

This folder contains the full plan and tooling for moving ASU Portal to a scalable one-file-per-module question bank format.

## Files in this folder

| File | Purpose |
| --- | --- |
| `schema.md` | Canonical v2 data specification. Follow this exactly. |
| `QuestionBankSchema.ts` | TypeScript model for the v2 JSON format. |
| `MEM-2.json` | Concrete example module file. |
| `scripts/migrate.ts` | Converts old split MCQ/essay files into one v2 module file. |
| `scripts/import-batch.ts` | Adds new batches of questions into an existing v2 module file. |
| `scripts/import-ready.ts` | Bulk import pipeline. Processes all `_ready` batches across all modules in one run. |
| `import-workflow.md` | Short workflow notes for repeated batch imports. |

```text

```

Example:

```text

```

This keeps your raw sources, clean import JSON, completed imports, reports, and rejected files separated.

## Target final module structure

Canonical files used by the website should live here:

```text
src/imports/year-{N}/semester-{N}/{moduleCode}.json
```

Examples:

```text
src/imports/year-2/semester-2/MEM-2.json
src/imports/year-2/semester-2/MCNS-2.json
src/imports/year-1/semester-2/MINF-1.json
```

Each module file contains all question types together: `mcq`, `truefalse`, `matching`, `essay`, `case`, and `fillblank`.

## Required implementation order for the website AI

Follow this exact order to avoid mistakes.

### 1. Add v2 runtime support

Update the app to consume `schemaVersion: 1` files directly.

Required app changes:

- Add `microbiology` to `SubjectColor` in `src/app/types.ts`.
- Add `subjectStyles.microbiology` in `src/app/types.ts`.
- Update any subject order/icon/name maps to include Microbiology:
  - ID: `microbiology`
  - Display name: `Microbiology`
  - Icon: `Biohazard`
  - ID key: `MICR`
- Update `src/app/data.ts` to prefer v2 files when `schemaVersion === 1`.
- For v2 files, do not infer metadata from folder names or filenames.
- For v2 files, do not infer subject color from topic strings.
- For v2 files, derive `subjectColor` from `subjects[].id`.
- For v2 files, do not use letter-to-index conversion because `correctIndex` is already canonical.
- Keep existing public functions working:
  - `isModuleActive`
  - `getModuleQuestionCounts`
  - `getChaptersForModuleAndMode`
  - `chapters`
  - `shuffleArray`
  - `findQuestionById`

Important compatibility detail:

The v2 canonical `question.id` is a string, while the old runtime type currently uses a number. Make the smallest safe app change so string IDs work everywhere, or store the canonical string ID separately while preserving stable runtime IDs. Do not break quiz answers, saved history, flagged questions, or `findQuestionById`.

### 2. Convert old data once

Run the migration script after the app can read v2 files.

```bash
npx tsx data-format-v2/scripts/migrate.ts
```

The script writes generated files to:

```text
data-format-v2/generated-imports/year-{N}/semester-{N}/{moduleCode}.json
```

Review the generated files, then move approved files into:

```text
src/imports/year-{N}/semester-{N}/{moduleCode}.json
```

### 3. Add new question batches seamlessly

Put incoming batches in the module's `_ready` folder.

Example:

```text
data-format-v2/question-intake/year-2/semester-2/MCNS-2 [Central Nervous System]/_ready/MCNS-2_batch_2026-06-11_neuro-final-revision_200.json
```

Run:

```bash
npx tsx data-format-v2/scripts/import-batch.ts \
  "data-format-v2/question-intake/year-2/semester-2/MCNS-2 [Central Nervous System]/_ready/MCNS-2_batch_2026-06-11_neuro-final-revision_200.json" \
  src/imports/year-2/semester-2/MCNS-2.json
```

After a successful clean import, move the batch from `_ready` to `_imported`, and move the generated report to `_reports`. If the report contains `needsReview`, keep the batch in `_ready` while fixing it, or move the problematic original to `_rejected`.

The importer automatically:

- Routes questions to the correct chapter.
- Routes questions to the correct subject.
- Creates a missing subject inside an existing chapter.
- Converts `correctAnswer: "C"` to `correctIndex: 2`.
- Generates the next canonical ID.
- Skips duplicate incoming questions.
- Removes duplicate questions already present in the existing target file.
- Writes a precise `.import-report.json` beside the incoming batch.

## Incoming batch format

Use this exact shape for smooth imports:

```json
{
  "moduleCode": "MCNS-2",
  "questions": [
    {
      "chapterTitle": "Brain Stem",
      "subject": "Anatomy",
      "topic": "Cranial Nerve Nuclei",
      "lecture": 4,
      "type": "mcq",
      "text": "Which cranial nerve exits from the pontomedullary junction?",
      "options": ["III", "V", "VI", "XI"],
      "correctAnswer": "C",
      "explanation": "The abducens nerve exits at the pontomedullary junction.",
      "keyConcept": "Cranial nerve VI exits at the pontomedullary junction."
    }
  ]
}
```

Preferred fields per question:

| Field | Required | Notes |
| --- | --- | --- |
| `chapterId` or `chapterTitle` | Yes | `chapterId` is safest. `chapterTitle` must match an existing chapter title/subtitle. |
| `subject` | Yes | One of Anatomy, Histology, Physiology, Biochemistry, Microbiology, Pathology, Pharmacology, Clinical, Parasitology, Psychiatry, Ophthalmology, ENT. |
| `topic` | Strongly recommended | The specific lecture/topic name from the syllabus (e.g. `"Bony Orbit"`, `"Lacrimal Apparatus"`). Used as the **primary** routing signal for smart auto-routing against `lectureNames`. |
| `lecture` | Strongly recommended | Integer lecture number. Defaults to chapter ID if absent. |
| `type` | Recommended | One of the six canonical types. Inferred only when obvious. |
| `text` | Yes | Question stem. |
| `options` | Required for MCQ/truefalse | Answer options. |
| `correctAnswer` or `correctIndex` | Required for MCQ/truefalse | `correctAnswer` can be A/B/C/D in incoming batches only. Canonical output uses `correctIndex`. |
| `explanation` | Recommended | Defaults to a generic rationale if absent. |
| `modelAnswer` | Required for essay | Importer flags essays without model answers. |
| `pairs` | Required for matching | Array of `{ premise, target }`. |
| `blanks` | Required for fillblank | Correct answers in order. |
| `subQuestions` | Required for case | Case sub-question types can be MCQ or essay only. |

## Duplicate behavior

The importer compares normalized question text plus options.

It handles duplicates in two ways:

1. Incoming duplicate of an existing question: skipped automatically.
2. Duplicate already inside the target bank: removed automatically, keeping the first occurrence.

All duplicate actions are recorded in the import report:

```json
{
  "skippedDuplicates": [
    {
      "matchedId": "MCNS2-CH4-ANAT-0501",
      "text": "Which cranial nerve exits from the pontomedullary junction?"
    }
  ],
  "removedExistingDuplicates": [
    {
      "keptId": "MCNS2-CH4-ANAT-0501",
      "removedId": "MCNS2-CH4-ANAT-0517",
      "text": "Which cranial nerve exits from the pontomedullary junction?"
    }
  ]
}
```

## Smart Lecture-Name-Based Auto-Routing

The importer includes a smart, lecture-name-based auto-routing algorithm. When questions are ingested, the script checks if the incoming question's `topic` (or `subject` or `chapterTitle`) matches any lecture name listed in the target module JSON file's `lectureNames` arrays:

1. **Exact-Match-First**: It normalizes and compares the incoming value to each entry in `lectureNames` of all subjects.
2. **Substring Match**: If no exact match is found, it looks for substring matches, provided that the matched value is not a generic subject name (like "Anatomy" or "Physiology").
3. **Automatic Lecture-Numbering**: If routed via smart routing, the question's `lecture` property is automatically assigned to the 1-based index of the matching lecture in the `lectureNames` array.
4. **Content-Based Routing Fallback**: If metadata matching fails (no `topic`/`subject`/`chapterTitle` matched any lecture name), the importer scans the question text itself against all `lectureNames`. It tokenizes the question text and each lecture name into significant words, scores each lecture by counting word matches, and requires ≥50% match with ≥2 hits (or 1 hit for single-word lecture names ≥6 chars). The highest-scoring lecture wins.
5. **Legacy Fallback**: If content-based routing also fails, the system falls back to chapter resolution (`chapterId` / fuzzy `chapterTitle` match) and subject inference.
6. **Review Flag**: If no routing method succeeds, the question is marked as `needsReview`.

**Full routing fallback chain**: `resolveSmartRouting` → `resolveContentRouting` → `resolveChapter` + `inferSubject` → `needsReview`

This ensures that for any module where `lectureNames` are populated in the database skeleton (such as the Special Senses module, `MSS-2.json`), incoming questions are sorted with high precision — even when metadata fields are missing.

## Review report


After each import, check the `.import-report.json` file written beside the incoming batch in the module's intake folder:

```text
data-format-v2/question-intake/year-{N}/semester-{N}/{moduleCode} [{moduleName}]/_reports/{batchFilename}.import-report.json
```

If `needsReview` is empty, the import completed cleanly.

If `needsReview` has items, fix only those questions in the incoming batch and rerun the importer.

## Exact prompt for generating future question batches

Use this prompt when another AI generates new batches:

```text
Convert these questions into a ASU Portal v2 incoming batch JSON.

Output one valid JSON object only. No markdown.

Use this shape:
{
  "moduleCode": "MCNS-2",
  "questions": []
}

For every question include:
- chapterId if known, otherwise exact chapterTitle
- subject: Anatomy, Histology, Physiology, Biochemistry, Microbiology, Pathology, Pharmacology, Clinical, Parasitology, Psychiatry, Ophthalmology, or ENT
- topic: specific lecture/topic name from the syllabus (e.g. "Bony Orbit", "Lacrimal Apparatus")
- lecture as an integer
- type: mcq, truefalse, matching, essay, case, or fillblank
- text
- explanation
- keyConcept when available

For MCQ/truefalse include options and correctAnswer as A/B/C/D or correctIndex as 0-based.
For essay include modelAnswer.
For matching include pairs as [{"premise":"...","target":"..."}].
For fillblank include blanks in order and acceptedAnswers when alternatives exist.
For case include subQuestions, and subQuestions can only be mcq or essay.
Do not invent chapter names. If unsure, preserve the source heading as chapterTitle.
```
